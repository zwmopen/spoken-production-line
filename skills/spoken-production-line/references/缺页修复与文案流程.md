# 缺页修复 → 三版本文案

## 缺页检查

1. 从当前会话最新已确认计划读取总页数与P1—PN主题，保存计划消息ID。不能用源图片数、母版图片数或“低于5张”替代计划。
2. 查启动消息之后实际交付的图片。区分原素材、工具输入、中间预览、原生生成结果、脚本产物；唯一文件及实际独立页面对应后才计数。ZIP不计一张图，重复引用不增计数。
3. 仍在回应：保留页面等待，不编辑、不刷新、不切走。已结束：逐页比对，全部匹配进入文案；缺页、分析出错、只有脚本裁剪结果则进入修复。
4. 有明确额度提示：记录已完成/缺失页码、提示及重试时间，冷却后再处理。不以会话读取429冒充生图额度限制。
5. 修复定位触发生成的用户消息，不限文本为1。可编辑则用production-confirm-prompt.txt替换原消息并发送；不可编辑则追加同一提示词。保存旧分支和原消息ID、新消息ID、实际重试提示、时间及结果，不删除旧文件。
6. 每账号只处理一套；重新发送后保持该会话直到结束。整套重做可能重复消耗额度，必须记录每次尝试，不把旧图和新图混成一套。没有结束或缺页证据不盲目重试。

## 独立文案技能组合

三版引擎为同级共享技能`teambuilding-web-copywriter`，独立维护。口述生产调用其SKILL.md、实际路由和必要参考，不复制一份规则，不调用通用xhs-copy-generator替代。

默认三个核心版本及顺序：小红书1｜自然攻略版、小红书2｜大纲方案版、抖音｜攻略版。保留U+2800复制空行、真实语料写法/标题路由与事实检查；抖音非营销。用户本次三版优先，不因成品治理另有11版流程扩大交付。

输入为本套原TXT、已确认计划、实际成图及事实账本；原料与已验收历史仅复用写法，不能移植事实。价格、人数、路线、季节项目缺证据则不虚构。成图存在错误事实先修图，文案不能为错误图编解释。

独立技能允许本地直出或网页CDP，必须把同一事实账本及该技能当前规则传给执行端，单发“出三版文案”不能证明已调用技能。当前生图任务进行中不插入文案消息打断。

生成后核验三个版本标题、正文、话题、平台边界与事实，归档为作品目录唯一`文案.txt`。现有文案使用既有COPY_FORMAT:MULTI合同，不创建多个TXT；修改前查历史与锁，整份替换并记录新旧哈希。作品manifest同步生产对话、来源、模板与耗时。完整图片及文案归档验收后才增加源素材使用次数。

## 缺页决策补充（2026-10-15）

逐套绑定最后已确认计划消息ID，核预期页码、独立原生成图、已下载文件和页序映射。实际少于计划才判缺页；3页计划实际3页不因低于5重做。回复仍在生成先等；明确限额不重发，记录缺失页码待恢复；已结束且部分合格优先仅补缺页/问题页，整套主题/母版串线或大量不合格才整套重做。补图命令写明同一任务/母版/本轮素材/具体缺页，不把脚本裁切、缩略图、重复文件或工具源指针当独立成图。缺文案只补文案，不重生图片。网页计划最多10页，出现15页先核是否为源图片数或其他产线合同，不能直接套网页页数。
