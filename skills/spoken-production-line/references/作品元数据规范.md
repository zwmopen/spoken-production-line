# 作品元数据与耗时

归档时合并进作品既有元数据或manifest，不另建互相冲突的身份信息。保留既有业务字段；账号凭据、Cookie、Token不得保存。

| 信息 | 建议字段 |
|---|---|
| 作品身份和主题 | workId、title、region、season、trafficType |
| 当前作品文件夹绝对路径 | localFolderPath |
| 生产账号与实例 | accountId、instanceId、productionMode |
| 当前生产对话链接及ID | conversationUrl、conversationId |
| 原素材笔记ID、源文件夹路径 | sourceNoteId、sourceFolderPath |
| 本轮实际上传文件与哈希 | sourceFiles、sourceSha256 |
| 稳定模板编号及名称 | templateId、templateTitle |
| 本地源模板文件夹路径 | localTemplatePath |
| 在线母版对话链接 | onlineTemplateConversationUrl |
| 计划和启动消息身份 | planMessageId、startMessageId、retryMessageIds |
| 实际确认提示词 | productionPrompt |
| 计划与实际逐页对应 | plannedPageCount、actualPageCount、pages |
| 成图格式与核验 | width、height、sha256、generationMethod、qaStatus |
| 云端归档地址 | driveFolderId、driveFolderUrl、syncedAt |
| 重试和失败信息 | attempts、errors、limitNotice |

## 耗时记录

每次尝试记录submittedAt、firstGenerationObservedAt、firstImageObservedAt、lastImageObservedAt、responseCompletedAt、completionObservedAt、downloadedAt、archivedAt，统一带时区。记录每页可获得的生成/观察时间。

服务端真实时间与本地观察时间分开。仅能看到“0:09发送、0:15观察结束”时，只能记录不晚于0:15结束及观察耗时上界，不能宣称精确生成6分钟。UI“思考了X分钟”是界面指标，不直接当整套端到端耗时。重试分别计时，保留首次提交和成功尝试。缺失时间为null，附时间来源。

停止按钮消失或“回答已完成”仅证明本轮回复结束，不证明计划全部图片成功。确认计划页数、实际原生独立成图数及对话展示齐全后才标记图片完成；下载及正式归档单独记状态。

## V3 统一证据合同（2026-10-15）
保留workId和既有业务字段，新增metadataSchemaVersion=3.0。JSON未知用null并写缺失原因；可视表显示“未取得”。当前路径与源路径必须是实际路径，路径迁移时同步更新，不凭旧标签认定文件仍存在。

| 模块 | 必须记录的内容 | 约束 |
|---|---|---|
| 身份与状态 | workId、metadataSchemaVersion、localFolderPath、deliveryStatus、metadataUpdatedAt | 物理保存、图片完成、验收通过、通知完成分开 |
| provenance | 实际渠道、账号身份及来源、实例、生产会话URL/ID、素材/计划/生成/文案消息ID、真实回执路径、执行者和脚本版本/哈希 | 声称的pipeline不等于实际执行证明；注册表URL不能代填生产URL |
| templateBinding | 稳定模板ID/名称、本地目录、原模板逐文件路径+哈希、各端注册链接、实际绑定状态 | 看过原图与真实会话身份才能通过绑定；不得从模板编号猜版式 |
| sourceBinding | 源笔记ID、本地目录、完整图片及TXT路径+哈希、本次读取或上传回执 | 历史素材文件列表不证明本次已上传或被读取 |
| plan | 计划消息ID/文件、页数、逐页角色、实际源文件名与事实映射、模板结构核对、确认消息ID | 每页绑定真实文件，不用不存在的简写名；修改计划保留版本 |
| attempts | attemptId、页码、实际提示词/版本及参考图、提交/完成与观察时间、工具结果、失败类型和恢复提示 | 原生工具结果与下载/裁剪操作分开；不覆写旧失败 |
| outputInventory | 物理文件路径/哈希/尺寸/字节、物理图数、已验收图数、文案路径/版本与哈希 | 文件存在和SHA唯一不代表视觉合格；未知验收数量不用物理图数代替 |
| acceptance | 执行者、时间、逐页实际观察、原图对照路径及哈希、未解决缺陷、验收状态与证据 | 禁止常量100分/0缺陷/hasSourceCompare=true；未看图不自动填通过 |
| timing | 全阶段事件时间、server/observed来源、上传/生成/文本分账、等待及重试耗时 | 缺失用null，不用文件mtime或目录命名冒充发生时间 |
| notifications | 事件、渠道与群ID、消息ID、发送/回读时间、幂等键 | 未发送不写已通知；正文从当前workId数据生成 |
| usage与cloudSync | 幂等usage事件、workId、计数回执；云端ID/URL/同步版本与校验时间 | 验收后才增加使用次数；云盘有链接不等于已同步 |
| metadataChangeLog | 时间、执行者、修改原因、旧版备份及关联workId | 返修另记attempt或revision，保留旧文件，不重新计数成新作品 |

## 每次素材使用的溯源事件

源素材 `.tags.json` 的 `usageEvents` 是逐次使用流水，至少包含：`workId`、`usedAt`（含时区及来源）、`account`/`channel`、`templateId`/`templateTitle`、`localTemplatePath`、真实 `conversationUrl`/`conversationId`、`sourceFolderPath`、`productPath`、`plannedPageCount`、`acceptedPageCount`、`deliveryStatus`。跨账号复用另填 `reuseOfWorkId` 与 `reuseReason`。

以 `workId` 幂等：先查同ID事件；若已有，补齐可证字段，不新增事件、不重复增加 `usageCount`。仅完整作品通过验收并物理落地后计一次；计划、上传、部分图、失败返修不计。字段没有证据时为 `null` 并注明缺失原因，不猜链接或模板。更新时保留原JSON副本或按项目安全写回机制留变更记录。

更新记录：2026-10-15 Codex 补全usageEvents的模板、对话、源/成品路径及workId幂等规则。

## 来源路径与交付状态幂等对账（2026-10-16）

每次正式计入素材使用次数前，交叉核对队列 `sourcePath`、manifest 的 `sourceFolderPath`/`sourceBinding`、当前 `.tags.json` 的物理父目录与 `localFolderPath`。优先用本轮上传回执及文件实存确认源目录；不得只信历史标签。路径不一致时，先保存旧版，再只修正能由物理目录/上传回执证实的字段，并把旧值、新值、修正原因和 workId 写入 `metadataChangeLog`。

usage 写入按 workId 幂等：同 ID 的 `usageEvents` 已存在时，只补齐路径、模板、会话、交付状态和通知回执等可证字段，不新增事件、不重复增加 `production.usageCount`；没有事件时，只有图片、文案、逐页验收和正式目录均通过后才新增一次。回读并确认 usage 计数后，再发/核验整套通知；飞书 GET 回读成功后，将同一 workId 的 manifest `usage/notifications`、交付验收回执、生产队列和滚动账同步为一致状态。任何一个回执仍标记 pending/in progress，都继续对账，不把局部成功当整套闭环。

本次 A T24 与 B T33 证明：物理源路径与 usage 事件已正确，但 manifest/验收/队列仍残留 pending。修复只对已有 workId 事件幂等补齐状态，没有重复增加使用次数。

## 阶段耗时诊断与经验积累

使用scripts/stage_timing.py记录真实阶段start/end及spanId，或StageTimer上下文；区分上传挂载、模型等待、下载、视觉验收、元数据归档、通知、额度等待、返修。下载公共入口已自动写download-stage.json。台账刷新会同步聚合阶段耗时统计.json。过去缺少阶段起点时留未知，不按文件mtime倒推，不把“文案完成到归档”的总间隔称为纯下载或纯验收耗时。

同阶段同口径已完成样本积累至少10次才将p50/p90作为初步基线；后续按账号、页数/素材规模拆组。当前计时器仅有阶段聚合，按账号/页数分组尚需样本完善，不宣称已接齐。超过p90的1.5倍且至少5分钟的在途阶段列内部排查候选，不自动报故障、不自动重发。排查分清平台等待、必要视觉修复、选择器/下载等技术故障、重复整理或协调等待。

可重复的机械动作固化代码；误判与根因修复写同一闭环清单/对应模块，带证据和验证；下次同类情况优先使用已验证办法。内部可解决问题不等用户提醒，不为了优化停掉正在正常工作的产线。
